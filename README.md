# 白木建設株式会社 現場監督採用LP

デザイン（トレースPNG）を画像として書き出し、Next.jsで見た目そのままWeb化した採用LPです。
**デザイン内の文字・写真・図・装飾はすべて画像のまま**使用しており、HTML/CSSでのデザイン再制作は行っていません。
例外は「実際に動作する必要がある要素」＝**お問い合わせフォームの入力欄**と**動画**のみで、これらはデザイン画像の該当位置へ透明な実要素を重ねています。

## 1. プロジェクト概要

- PC版・SP版のデザインをそれぞれ13セクションに分割し、WebP画像として書き出し
- 画面幅に応じてPC画像／SP画像を自動切り替え（`<picture>`、不要な側はダウンロードされない）
- 画像の上に、透明なクリック領域（ヘッダーナビ／CTA／フッターリンク）を重ねる
- 動画枠には YouTube（限定公開可）／Googleドライブ／動画ファイルを埋め込み、枠を埋めるように表示
- 各動画枠の拡大ボタンから、16:9のまま／ブラウザのネイティブ全画面で視聴可能
- お問い合わせフォームは、デザイン画像の入力欄の上に透明な `<input>` / `<textarea>` を重ねて機能させる
- 外部URL・動画URL・フォーム送信先はすべて環境変数で一元管理（コンポーネントへの直書きなし）

## 2. 使用デザインデータ

```
source/トレースPC版.jpg   (2048 x 18280 px, 2倍)   ← 現在使用中
source/トレースSP版.jpg   (750 x 25159 px, 2倍)    ← 現在使用中
source/トレースPC版.png   (1024 x 9140 px, 等倍)   ← 旧データ（未使用）
source/トレースSP版.png   (375 x 12580 px, 等倍)   ← 旧データ（未使用）
```

`source/` 配下は元データであり、Vercelへ公開されるのは `public/design/` の書き出し済み画像のみです。

### 解像度について

表示上の基準サイズは **PC 1024px / SP 375px** ですが、元データは**その2倍の解像度**を使っています。
これにより、Retina（2倍以上）の画面でも文字や細い線がぼやけません。

**元データを差し替えるだけで解像度を上げられます。**
`scripts/generate_design_assets.py` は `source/` にある同名ファイルのうち
**最も横幅の大きいものを自動で採用**し、セクション境界も画像サイズから自動換算します。
そのため、3倍の書き出しへ差し替えても**境界値やコードの修正は不要**です。
（境界値は `PC_BOUNDARIES` / `SP_BOUNDARIES` に「1倍基準」で記述されています）

## 3. PC・SPの切り替え条件

- 0〜767px: SP画像を表示（最大幅375px、中央寄せ）
- 768px以上: PC画像を表示（最大幅1024px、中央寄せ）
- `<picture>` + `<source media="(max-width: 767px)">` により、該当しない側の画像はダウンロードされません
- 320〜430pxで崩れないこと、原寸を超えて拡大されないことをPlaywrightで確認済み

### 画面幅が広いときの左右の埋め方

デザイン本体は原寸（PC 1024px）で中央に置くため、それより広い画面では左右に余白が生まれます。
この余白は、**そのセクション画像自体を強くぼかしたものを背景に敷いて**埋めています
（`.design-section::before`、`filter: blur(36px)`）。

- 縦方向は原寸と同じ比率で配置するため、背景色の切り替わりが本体とぴったり一致します
- フッターの濃緑や募集要項の淡緑などの帯は、画面端まで途切れずに続きます
- 端まで写真があるセクション（ファーストビュー・お問い合わせ）でも、縞にならず自然になじみます
- **デザイン本体は拡大していない**ため、文字や細い線の画質は一切劣化しません

## 5. 画像再生成方法

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install pillow
python scripts/generate_design_assets.py
```

または

```bash
npm run generate:assets
```

出力先は `public/design/pc/` と `public/design/sp/`、
画像サイズ一覧は `src/config/generatedImageSizes.ts` と `public/design/manifest.json` に自動生成されます（手動編集不可）。
OGP画像（`public/ogp.jpg`）とfavicon類もこのスクリプトで生成されます。

## 9. 動画の埋め込み仕様

### 現在の割り当て

4つの枠すべてに動画を割り当て済みです（`src/config/videos.ts` の `defaultUrl`）。
**4本ともYouTubeの限定公開（Shorts＝縦型9:16）** です。

| 動画枠（セクション） | 割り当てた動画 | 動画ID |
|---|---|---|
| 会社紹介動画（現場監督の仕事とは？） | 白木建設の好きなところ | `xuvIO0sUyl8` |
| 社員インタビュー（キャリアプラン） | 社員インタビュー（未経験） | `4htlNrI8mBI` |
| 実際の現場一日紹介（先輩社員の1日） | 施工管理の1日 | `pfhUZS8shfc` |
| 社長からのメッセージ枠 | 会社全体紹介 | `jogdAuUeZzM` |

差し替えは `src/config/videos.ts` の `defaultUrl` を書き換えるか、
対応する環境変数を設定してください（**環境変数が優先されます**）。

> **限定公開の動画をアップロードする際の注意**
> - 公開設定は「限定公開」にしてください。**「非公開」は埋め込みでは再生できません**
> - 「視聴者：子ども向けです」を選ぶと埋め込みが禁止されます。「子ども向けではありません」を選んでください

### 対応しているURLの種類

URLの種類で埋め込み方法が自動的に切り替わります。

| 入れるURL | 埋め込み方法 |
|---|---|
| YouTube（限定公開URLも可）<br>`https://youtu.be/xxxx`<br>`https://www.youtube.com/watch?v=xxxx`<br>`https://youtube.com/shorts/xxxx` | `youtube-nocookie.com` の iframe（`loading="lazy"`） |
| Googleドライブ<br>`https://drive.google.com/file/d/xxxx/view` | ドライブの `preview` iframe（`loading="lazy"`） |
| それ以外（`.mp4` 等） | `<video controls playsInline preload="metadata">` |

`?si=`（共有ボタンのトラッキング）、`?t=90` / `?t=1m30s`（再生開始位置）も解釈します。
YouTube・ドライブのURLなのに動画IDが取り出せない場合（チャンネルURL、フォルダURL、
IDの打ち間違いなど）は、**壊れたプレーヤーを出さずに何も描画しません**。

**URLを差し替える手順（コード変更なし）**

1. YouTubeへ動画をアップロードし、公開設定を「限定公開」にする
2. 「共有」で取得したURLをコピー
3. Vercelの環境変数（またはローカルの `.env.local`）へ設定する

   ```
   NEXT_PUBLIC_COMPANY_VIDEO_URL=https://youtu.be/xxxxxxxxxxx
   ```
4. 再デプロイすると、その枠だけが差し替わります

> **Googleドライブを使う場合の注意**
> ドライブのURLもそのまま埋め込めますが、本番運用には次の弱点があります。
> - アクセスが増えると再生回数の上限（クォータ）で再生できなくなることがある
> - ドライブ独自のプレーヤーUIが表示される
> - 回線に応じた画質の自動切り替え（アダプティブ配信）がされないため、読み込みが重い
> - ファイルの共有設定が「リンクを知っている全員」である必要がある
>
> 現在は4枠ともYouTubeの限定公開に切り替え済みです。

### 枠と動画の比率

デザイン上の動画枠は横長を前提にしていますが、**割り当てた4本はすべて縦型（9:16）** です。
そのため、PCとSPで扱いを分けています。

#### SP：動画を等倍で表示する

スマホでは動画が主役になるため、**枠をデザイン値より広げ、動画を等倍（9:16そのまま）で再生**します。
縮小もトリミングも起きません。

| 動画枠 | デザイン上の枠 | 実際の表示 |
|---|---|---|
| 会社紹介動画 | 335×190 | **335×596（9:16 等倍）** |
| 社員インタビュー | 335×189 | **335×596（9:16 等倍）** |
| 実際の現場一日紹介 | 335×189 | **335×596（9:16 等倍）** |
| 社長からのメッセージ | 335×189 | **335×596（9:16 等倍）** |

※ 数値は画面幅375pxの場合。枠の幅は画面幅に比例するため、320pxなら286×508になります。

枠が縦に伸びる分、**セクションの下へ同じ高さの余白を足して**次のセクションへ重ならないようにしています。
4枠とも動画の下端とセクションの下端がぴったり一致します（Playwrightで検証）。

- 余白の高さは `src/components/ResponsiveDesignSection.tsx` の `overflowBelowImage()` が
  「画像の表示幅を1とした割合」で算出するため、画面幅が変わっても崩れません。
- 余白の色は、セクション画像の下端の色（`generatedImageSizes.ts` の `bottomColor`、
  画像生成時に自動で算出）を使います。
- 左右のぼかし背景は、画像部分の高さぶんだけ敷いてから同じ色で続けているため、
  画像と余白の境目に線が出ません（`--band-sp`）。
- **4枠とも動画枠の下は元々余白**だったため、デザインの文字や写真は一切隠れません。
- 16:9の動画へ差し替えると、枠はデザイン値とほぼ同じ高さに戻り、余白も自動的に0になります。

#### PC：枠を広げて大きく表示する

PCも、デザインの枠が動画の比率と大きく違う3枠は**枠を縦に広げて**動画を大きく表示します。

| 動画枠 | デザイン上の枠 | 実際の表示（枠 / 動画） |
|---|---|---|
| 会社紹介動画 | 951×194 | **951×615 / 346×615** |
| 社員インタビュー | 870×354 | **870×615 / 346×615** |
| 実際の現場一日紹介 | 341×615 | 341×615 / 346×615（デザインのまま） |
| 社長からのメッセージ | 774×378 | **774×615 / 346×615** |

※ 数値は画面幅1024px以上の場合。デザイン画像は原寸（1024px）を上限に表示するため、これ以上は変わりません。

動画の高さは4枠とも **615px** に揃えています。これはデザイン内で唯一の縦長枠
「実際の現場一日紹介」(341×615) の高さで、`src/config/videos.ts` の
`pcEnlargedVideoHeight` で変更できます。

- 広げるのは**枠の高さだけ**です。左端・上端・幅はデザインどおりで、動画は枠の中央に置かれます
- 枠の左右に残る面は、デザインのグレー枠と同じ色・角丸で描いています
  （縦型動画を横長の枠で再生したときの一般的な見え方＝左右が余白になる状態です）
- SPと同じく、広げた分はセクション下部の余白が受け止めます
- 「実際の現場一日紹介」の枠は**元から縦長（0.55:1 ≒ 9:16）**で動画がぴったり収まるため、デザインのままです

**デザインへの影響**
「現場監督の仕事とは？」「キャリアプラン」の2枠は、動画枠の下がもともと余白のため、
文字や写真は一切隠れません。
「社長からのメッセージ」だけは、枠の下にある**薄い線画の背景イラストの一部**に枠が重なります
（イラストは枠の左側に見えたまま残ります）。

16:9の動画へ差し替えた場合、枠の比率がデザイン値に近づくため、
枠を広げずデザインどおりのサイズに戻ります。

### 全画面表示

枠に対して動画が小さく見える枠（＝左右に余白が出るPCの3枠）にだけ、
右上に**拡大ボタン**（`⤢` アイコン）を重ねています。

| 操作 | 挙動 |
|---|---|
| 拡大ボタンを押す | 画面全体を覆うモーダルが開き、動画が**本来の比率のまま**大きく表示されます |
| モーダル内の「全画面」ボタン | ブラウザのネイティブ全画面API（`requestFullscreen`）へ切り替えます |
| `✕` / 背景クリック / `Escape` | モーダルを閉じ、フォーカスは元の拡大ボタンへ戻ります |
| プレーヤー自身の全画面ボタン | iframe に `allowFullScreen` を付与済みのため、YouTube側の全画面もそのまま使えます |

**SPと、PCの「実際の現場一日紹介」枠には拡大ボタンを出していません。**
すでに等倍で表示されており拡大するものが残っていないうえ、
プレーヤー自身の全画面と操作が二重になるのを避けるためです。

拡大中は、**枠の中のプレーヤーをDOMから取り外します**。
同じ動画のiframeが2つ同時に存在すると、音が二重に鳴ったり全画面表示が二重に見えたりするためです。

モーダルの比率は CSS変数 `--video-aspect` で動画ごとに切り替わるため、
16:9の動画へ差し替えても自動的に追従します。
モーダルが開いている間は背景（`body`）のスクロールを固定し、
`createPortal` で `document.body` 直下へ描画することで
セクションの `overflow: hidden` にクリップされないようにしています。

## 9-2. SP版 三本線メニュー

SP版ヘッダー右上の三本線をタップすると、ページ内遷移用のメニューが開きます。

- 項目は `src/config/mobileNav.ts` で管理（このLPに実在するセクションのみ、遷移先の推測はしていません）
- デザインに「開いた状態」が存在しないため、パネルの配色は
  デザインから採取した色（フッターの濃緑 `#1b3b2a` / ボタンの緑 `#30ac5f`）で構成しています
- パネルはセクションの `overflow: hidden` に切られないよう、`createPortal` で `body` 直下に描画しています
- 開いている間は背面のスクロールを固定、`Escape` と `✕` で閉じられます
- PC表示（768px以上）では、デザインに三本線が存在しないため描画しません

| メールアドレス | ◯ | 形式をサーバー側で検査 |
| メッセージ | ◯ | 5000文字まで |
| 生年月日 | ◯ | **カレンダーから選択**（`<input type="date">`）。1900年〜今日まで |
| 性別 | ◯ | 選択式（男性／女性／その他） |

必須・文字数・選択肢は `src/config/contactForm.ts` で定義し、画面と受け口の両方が
同じ定義を見ています（増やすときは1か所の変更で済みます）。

- デザイン画像の白い入力欄の上に、透明な `<input>` / `<textarea>` を重ねています（見た目は画像のまま）
- 座標は `src/config/contactForm.ts` でPC/SP別に管理
- 送信状態（送信中／完了／失敗）は `aria-live` で読み上げ対応
- 画面に出ない「おとり」の入力欄を1つ置き、自動投稿プログラムが埋めた送信は黙って捨てます

### 入力するとデザインの例文を隠す仕組み

入力欄は透明なので、そのままだと入力した文字の下にデザイン画像の例文
（「例：山田 太郎」など）が残って二重に見えてしまいます。
そこで **値が入ったら入力欄を白で塗りつぶし**、下の例文を隠しています。
白と角丸はデザインの枠と同じ（実測: PC 6px / SP 5px 相当）なので、見た目は変わりません。

- 文字入力欄 … デザインと同じ文字列を `placeholder` に入れたうえで透明にし、
  `:placeholder-shown` で入力の有無を判定
- 生年月日・性別 … `placeholder` を持てないため、`:valid` / `:invalid` で判定。
  未入力のうちはブラウザ既定の「年/月/日」「選択してください」とカレンダーアイコンも隠す
- 生年月日は枠のどこを押してもカレンダーが開きます（`showPicker()`、非対応ブラウザでは手入力）

### デザイン画像の差し替えと描き替えについて

お問い合わせセクションだけ、全ページのトレースではなく
**セクション単体の画像**（`source/sections/12-contact-pc.jpg` / `-sp.jpg`）を使っています。
`scripts/generate_design_assets.py` の `SECTION_OVERRIDES` に登録されたセクションは、
全ページのトレースを切り出す代わりにこのファイルが使われます。
一部のセクションだけデザインが更新されたとき、全ページを書き出し直さずに差し替えられます。

さらに、同スクリプトが画像へ次の描き替えを行っています（元データとの差分）。

| 元データ | 実際の表示 |
|---|---|
| ラベル「年齢」 | **「生年月日」**（元の文字は同じ行の写真で消し込み、描き直し） |
| プレースホルダ「例：30」 | **「例：1998年4月1日」** |
| 生年月日・性別に必須バッジ無し | **両方に「必須」バッジを追加** |

- 文字の描画には Noto Sans JP を使用（`scripts/fonts/` に必要な文字だけのサブセットを同梱、SIL Open Font License 1.1）
- **元データ側でラベルと必須バッジが直されたら、この描き替えは不要になります。**
  `apply_contact_form_edits` の呼び出しを外してください
- 差し替え元の解像度は PC 1536px幅 / SP 563px幅（表示は PC 1024px / SP 375px なので約1.5倍）。
  他のセクションは2倍のため、**この部分だけ高精細な画面でわずかに解像感が劣ります**。
  2倍（PC 2048px / SP 750px）で書き出し直したものに差し替えれば解消します

### 送信の流れ

```
ブラウザ ──POST──▶ /api/contact ──POST──▶ Google Apps Script
                   (同一オリジン)          (scripts/contact-form.gs)
                                               ├─ スプレッドシートへ1行追記
                                               ├─ 採用担当へ通知メール
                                               └─ お問い合わせ者へ自動返信メール
```

ブラウザから直接 Apps Script を叩かないのは、次の理由からです。

- Apps Script のURLがページのHTMLに出ないため、いたずら送信の的になりにくい
- クロスオリジン（CORS）の制約を受けない
- 送信元でまとめて入力チェックできる

### お問い合わせ内容を失わないための仕組み

送信が途中で失敗してもお客様の入力が消えないよう、4段階で守っています。

| 段階 | 内容 |
|---|---|
| 1. 再試行 | 保存先へ届かなかった場合、0.3秒・0.9秒あけて最大3回試します。一時的な不調はここで吸収されます |
| 2. 控えの送り先 | `CONTACT_BACKUP_URL` を設定しておくと、本来の送り先が駄目なときだけそちらへ記録します |
| 3. ログへの記録 | どこにも記録できなかった場合、内容そのものをVercelのログへ残します。あとから手作業で拾い直せます |
| 4. 端末への一時保存 | 送信に失敗したら、入力内容をお客様の端末へ保存します。ページを閉じても書き直さずに済み、送信できたら消えます |

> **3のログについて**
> ログには氏名・連絡先などの個人情報が含まれます。閲覧できる人を絞り、
> 拾い直したあとは放置しないでください。検索するときは `[contact] 保存先へ届きませんでした` で絞り込めます。
> Vercelのログには保存期間があるため、**気づける体制（Vercelのアラート等）とあわせて**運用してください。

**控えの送り先（`CONTACT_BACKUP_URL`）の作り方**

本来の送り先と同じ `scripts/contact-form.gs` を、**別のスプレッドシート**に紐づけて
もう1つデプロイし、そのURLを設定するだけです。設定ファイルの `SHARED_SECRET` は
本来の送り先と同じ値にしてください。通知メールが二重に届くのを避けたい場合は、
控え側の設定ファイルで `IS_BACKUP = true` にしてください（`NOTIFY_TO` は空のままで構いません）。
控え側は通知メールを送らず、シートへの記録とお問い合わせ者への自動返信だけを行います。
控えの動作確認は、メールを送らずシートへの書き込みだけを試す `testSheetOnly()` を使ってください。

`/api/contact` の応答:

| 状況 | HTTP | 内容 |
|---|---|---|
| 正常 | 200 | `{ ok: true }` |
| 入力不備 | 400 | `{ ok: false, error: "invalid_input", invalid: [...] }` |
| 中継先が未設定 | 503 | `{ ok: false, error: "not_configured" }` |
| 控えへ記録 | 200 | `{ ok: true, viaBackup: true }` |
| どこにも記録できず | 502 | `{ ok: false, error: "forward_failed" }`（内容はログへ） |

生年月日は画面からは `1998-04-01` の形で届きます。メールには読みやすい `1998年4月1日` を、
スプレッドシートには並べ替え用の `1998-04-01` も併せて記録します。
手入力や他の経路から `1998年4月1日` `1998/4/1` `１９９８年４月１日` のような表記で届いた場合も解釈します。
実在しない日付（2月30日など）や未来の日付の場合は、並べ替え用の列を空にします。

### メールとスプレッドシートの設置手順

受信処理は Google Apps Script で行います。設置手順は `scripts/contact-form.gs` の冒頭コメントに
そのまま書いてあります。要点は次のとおりです。

1. Googleドライブでスプレッドシートを新規作成する
2. そのシートで「拡張機能 > Apps Script」を開き、`scripts/contact-form.gs` の内容を貼り付ける
3. 「ファイル」の「＋ > スクリプト」で **「設定」** というファイルを作り、
   `scripts/contact-form-settings.gs` の内容を貼り付けて、宛先と合言葉を入力する
4. 「デプロイ > 新しいデプロイ > ウェブアプリ」（実行者＝自分／アクセス＝全員）でデプロイする
5. 表示されたURLを Vercel の `CONTACT_FORWARD_URL` へ、`SHARED_SECRET` と同じ値を
   `CONTACT_SHARED_SECRET` へ設定して再デプロイする

> **設定を本体と分けている理由**
> 宛先や合言葉を本体（`コード.gs`）に書いていると、スクリプトを更新するために
> 貼り替えたときに設定ごと消えてしまいます。
> **設定ファイルは一度作ったら触らず、更新は本体だけを貼り替えてください。**

設置確認用に、Apps Script エディタ上で実行できる関数を2つ用意しています。

| 関数 | 用途 |
|---|---|
| `checkSettings()` | 宛先の設定漏れ・メール権限・その日に送れる残り通数を「実行ログ」に表示 |
| `testSubmission()` | シートへの追記と、通知メール・自動返信メールの送信を1回試す（本番用） |
| `testSheetOnly()` | メールを送らず、シートへの書き込みだけを1回試す（控え用） |

メール送信の結果は、シートの一番右の列（`メール送信`）に
`通知:送信済み / 自動返信:送信済み` のように記録されます。
失敗した場合も理由がここに残るため、届かないときはこの列を確認してください。

スプレッドシートに記録される列:

`受信日時 / お名前 / フリガナ / 生年月日 / 生年月日(YYYY-MM-DD) / 性別 / 電話番号 / メールアドレス / メッセージ / メール送信`

**全7項目が必須**です。

> **メール送信数の上限**
> Apps Script の `MailApp` は1日あたりの送信数に上限があります
> （無料のGoogleアカウントで100通／Google Workspaceで1,500通）。
> 1件のお問い合わせにつき2通（通知＋自動返信）送信します。

## 13. クリック領域・座標の修正方法

透明クリック領域は `src/config/clickAreas.ts`、動画枠は `src/config/videos.ts`、
フォーム入力欄は `src/config/contactForm.ts` で一元管理しています。
いずれも**セクション画像を基準とした相対値（%）**です。

```
left   = 対象左端X ÷ セクション画像の横幅 × 100
top    = 対象上端Y ÷ セクション画像の高さ × 100
width  = 対象横幅   ÷ セクション画像の横幅 × 100
height = 対象高さ   ÷ セクション画像の高さ × 100
```

1. `?debugLinks=true` でズレを確認
2. 対象の `id` を該当の設定ファイルで検索し、`pc` または `sp` の値を調整
3. 保存して再読み込みし、再確認

PC専用要素（ヘッダーの各ナビ項目）は `pc` のみ、SP専用要素は `sp` のみを持たせます。

## 14. URL未設定時の挙動

- 対応する透明リンク（`<a>`）は通常表示では**生成されません**（DOM上に存在しない）
- 動画も**描画されず**、デザイン画像のグレー枠がそのまま見えます
- `href="#"` やダミーURLへのフォールバックは行いません
- フォームは送信ボタンが無効化されます
- `?debugLinks=true` では、斜線パターン＋「URL未設定」ラベルとして可視化されます

## 15. Playwrightテストの実行方法

```bash
npm run test:e2e
```

`webServer` 設定により、`npm run build && npm run start` が自動実行されます。
テストプロセスは `.env.local` / `.env` を読み込むため、環境変数の設定状況に応じて期待値が自動で切り替わります。

テスト内容（138件。うち1件は該当枠がないためスキップ）:

- 320〜1920px（15段階）での横スクロール有無
- 767px以下でSP画像・768px以上でPC画像のみが表示されること（`currentSrc`で検証）
- 原寸（PC 1024px / SP 375px）を超えて拡大されないこと、縦横比が元データと一致すること
- 全13セクションの存在
- 内部リンク（`#contact` `#numbers` `#requirements`）の遷移先
- 外部リンクの `target="_blank"` / `rel="noopener noreferrer"` / `aria-label`
- PC用／SP用リンクが混在表示されないこと
- URL未設定時にダミーリンクが生成されないこと
- 動画が本来の比率を保ち、枠に対して cover / contain が正しく選ばれること
- 4枠ともYouTube埋め込みで、`youtube-nocookie` を使うこと
- 枠内で小さく見える枠にだけ拡大ボタンが出ること、モーダルが動画本来の比率で開くこと、背景スクロール固定・`Escape`で閉じること
- 拡大中に同じ動画のプレーヤーが二重にならないこと
- SPの4枠が動画本来の比率（9:16）で、拡大も縮小もトリミングもなく表示されること
- SPで伸ばした枠の下端がセクション下端と一致し、次のセクションに重ならないこと・横スクロールが出ないこと
- PCの4枠が615px相当の高さで表示され、広げた枠の下端がセクション下端と一致すること
- フォームの実入力・PC/SP出し分け・送信ボタンの有効/無効
- 全7項目が必須で、デザインどおりの順に並んでいること
- 性別が選択式で、用意した選択肢だけを選べること
- 入力するとデザインの例文が隠れること（二重表示にならないこと）
- 生年月日がカレンダー入力で、未来の日付を選べないこと
- 送信できなかった入力内容が、ページを開き直しても書き戻されること
- おとりの入力欄が画面外にあること
- `/api/contact` の入力検査（必須・文字数・メール形式・選択肢・不正なJSON）とおとり欄の扱い
- デバッグモードでの可視化、`lang="ja"`、sr-only h1、画像alt空、キーボードフォーカス

## 16. 画像を差し替える際の注意事項

- 元データ（`source/`）を差し替えたら、`scripts/generate_design_assets.py` の `PC_BOUNDARIES` / `SP_BOUNDARIES` を実際の画像に合わせて再調整してから再生成してください
- 2倍解像度の画像へ差し替える場合、境界値も2倍にする必要があります
- 余白色（`bottomColor`）は画像下端から自動算出されるため、手で書く必要はありません
- 画像を手動で差し替える場合は、**ファイル名・出力先・縦横比を変更しない**でください
- デザインが変わった場合は、`?debugLinks=true` でクリック領域・動画枠・フォーム座標を必ず再確認してください
